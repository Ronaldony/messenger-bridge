# Messenger Bridge 사용 가이드

ChatGPT, Telegram, Discord처럼 대화가 이어지는 서비스를 서로 연결해 메시지를 전달하고, 실제 도착 여부까지 확인하도록 돕는 Agent Skill입니다.

원하는 출발지, 도착지, 전달할 내용과 도착 확인 여부를 자연어로 요청할 수 있습니다. 필요한 연결 수단은 스킬이 현재 환경에서 탐색합니다.

> **빠른 사용 예시**
>
> `ChatGPT의 마지막 답변을 Telegram으로 보내고 싶어. 먼저 사용할 ChatGPT 대화 세션과 Telegram 채널을 확인받아 줘.`

## 1. 설치하기

Windows에서는 PowerShell, macOS와 Linux에서는 터미널을 엽니다. 먼저 다음 명령으로 Node.js가 준비되어 있는지 확인하세요.

```bash
node --version
```

버전 번호가 나오면 준비된 상태입니다. 명령을 찾을 수 없다는 메시지가 나오면 [Node.js 공식 사이트](https://nodejs.org/)에서 LTS 버전을 설치한 뒤 터미널을 다시 여세요.

이제 다음 명령을 실행합니다. 설치 과정에서 대상 에이전트를 묻는다면 Codex를 선택하세요.

```bash
npx skills add Ronaldony/messenger-bridge --skill messenger-bridge -g -a codex
```

`-g`는 모든 프로젝트에서 사용할 수 있도록 사용자 영역에 설치한다는 뜻입니다. 현재 프로젝트에서만 사용하려면 `-g`를 빼세요.

설치 확인:

```bash
npx skills list -g -a codex
```

## 2. 요청하기

설치 후 원하는 전달 결과를 자연어로 요청합니다.

```text
ChatGPT 답변을 Telegram의 가족 채널로 보내줘.
```

```text
이 Telegram 메시지를 Discord의 #공지 채널로 전달하고 도착 여부도 확인해줘.
```

```text
Telegram의 새 메시지를 현재 Codex 작업이 끝나기 전까지 기다렸다가 ChatGPT에 전달해줘.
```

스킬이 자동으로 선택되지 않는 경우 요청 앞에 `$messenger-bridge`를 붙이세요.

```text
$messenger-bridge를 사용해 ChatGPT 응답을 Telegram으로 보내줘.
```

## 3. 동작 방식

Messenger Bridge는 다음 순서로 작업합니다.

1. 어느 서비스에서 어느 서비스로 보낼지 파악합니다.
2. 이미 연결된 안전한 도구가 있는지 먼저 확인합니다.
3. 메시지를 읽거나 보내기 전에 출발 세션과 도착 채널을 항상 표시하고 사용자에게 확인받습니다.
4. 확인된 출발지에서 본문을 읽고, 전송할 본문·변환 여부·비용 가능성을 확인합니다.
5. 승인된 메시지를 한 번만 보내고 가능한 경우 확인된 도착지 기록을 다시 읽어 검증합니다.

Telegram 연동은 실제 검증된 예시입니다. Discord나 다른 대화 서비스는 현재 환경에서 호환되는 연결 수단을 먼저 찾고, 준비되지 않았다면 가장 안전한 설정 방법과 대안을 제안합니다.

## 채널과 세션 확인

최초 요청에 채널이나 대화 이름을 적었더라도 스킬은 이를 후보로만 취급합니다. 메시지 본문을 읽거나 새 메시지를 기다리거나 전송하기 전에 다음 항목을 보여주고 새 답변으로 확인을 요청합니다.

- 출발 메신저, 로그인 또는 어댑터 세션, 대화·채널·스레드 이름과 식별자
- 도착 메신저, 로그인 또는 어댑터 세션, 대화·채널·스레드 이름과 식별자
- 전달 방향과 실행할 읽기·대기·전송 작업

후보가 하나뿐이거나 이전에 사용한 채널이어도 자동으로 선택하지 않습니다. 사용자가 확인한 도착지에서 방금 보낸 메시지를 검증하기 위한 재조회만 같은 확인 범위에 포함됩니다.

## 처음 연결할 때 필요한 것

이미 사용할 수 있는 연결이 있으면 그대로 재사용합니다. 연결이 없다면 스킬이 설치, 로그인 또는 권한 설정이 필요한 이유를 설명하고 진행 승인을 요청합니다.

- 비밀번호, 인증 코드, API 키, 세션 문자열을 채팅창에 붙여 넣지 마세요.
- 로그인은 서비스의 공식 로그인 화면이나 로컬 보안 입력 절차에서 진행합니다.
- 유료 API, 호스팅, 터널 또는 프리미엄 기능이 필요하면 비용이 발생하기 전에 반드시 별도 승인을 받습니다.
- 같은 목표를 달성할 수 있다면 추가 비용이 없는 기존 연결을 우선합니다.

## 도착 확인 수준

요청에 `실제 도착했는지도 확인해줘`를 포함하면 가장 강한 검증을 시도합니다.

| 결과 | 뜻 |
| --- | --- |
| `accepted` | 받는 서비스가 전송 요청을 성공으로 처리했습니다. |
| `delivered` | 안정적인 메시지 ID 같은 배달 증거를 받았습니다. |
| `verified` | 도착지 기록을 다시 읽어 본문과 식별 표시가 일치함을 확인했습니다. |

전송 성공 결과가 나온 뒤에는 검증 수준을 높이기 위해 같은 메시지를 다시 보내지 않습니다. 검색 반영이 늦으면 재전송 대신 최근 메시지 기록을 읽어 확인합니다.

## 안전한 기본 동작

- 일반 요청은 메시지 한 건을 한 번 전달하는 `one-shot` 방식입니다.
- 전송 결과가 불확실해도 자동으로 반복 전송하지 않습니다.
- 예약 작업이나 계속 실행되는 백그라운드 감시는 자동으로 만들지 않습니다.
- 본문이나 첨부파일을 바꿔야 하면 변경 내용을 먼저 알리고 승인받습니다.
- Windows, macOS, Linux에서 같은 역할 모델을 사용합니다. 저장소의 PowerShell 파일은 Windows용 선택 도우미일 뿐 필수 구성요소가 아닙니다.

## 핵심 개념

Messenger Bridge는 다음 세 역할을 기준으로 연결을 설계하고 작업 결과를 설명합니다.

| 역할 | 설명 |
| --- | --- |
| Sender | 보낼 메시지가 있는 출발지 |
| Receiver | 메시지를 받을 도착지 |
| Bridge | 출발지와 도착지를 안전하게 연결하는 전달 규칙 |

전체 검증에서는 Sender, Receiver, Bridge가 각각 통과해야 최종 성공으로 판정합니다.

## 제한 사항

- 대상 서비스에 로그인하거나 메시지를 보낼 권한이 필요합니다.
- 서비스마다 지원하는 글 형식, 첨부파일, 스레드와 확인 기능이 다를 수 있습니다.
- Codex의 현재 작업이 끝난 뒤 스스로 다시 깨어나는 상시 자동화는 이 스킬의 범위가 아닙니다.
- 상시 감시나 예약 전달이 필요하면 별도의 실행 환경과 명확한 승인이 필요합니다.

## 문제 해결

문제가 발생하면 증상, 원하는 결과와 재전송 허용 여부를 요청에 포함하세요.

```text
Telegram으로 전송됐다고 나오지만 메시지가 보이지 않아. 재전송하지 말고 확인해줘.
```

```text
Discord 연결 방법을 모르겠어. 비용이 들지 않는 방법부터 찾아서 안내해줘.
```

스킬은 실패 지점을 출발지, 도착지, 연결 규칙 중 하나로 구분하고 가장 작은 다음 조치를 안내합니다.
